# AI 语音代打电话工具 — 日本落地 MVP 产品需求文档（PRD）

**文档版本**: v1.0  
**目标市场**: 日本（始发站），可逐步扩散至其他地区  
**MVP 受众**: 日本在华驾驶学习微信群成员（约 1000 人）→ 在日华人  
**产出目的**: 商业可行、可落地的产品闭环与外部依赖清单

---

## 1. 产品愿景与定位

### 1.1 愿景

面向 C 端用户的 **AI 代打电话助手**：用户通过文字提交诉求与背景信息，由 AI 以**仿真人语音电话**代用户致电指定对象（如商户、机构、客服），完成咨询、订座、购物等诉求，并将结果通过用户授权的方式（文字/语音/电话/短信/邮件）反馈给用户；单案内支持多轮通话与记忆，形成可追溯的闭环。

### 1.2 市场与节奏

- **始发站**: 日本。原因：在日华人有大量「打电话」刚需（日语不流利、时间不便、怕说错），且你已有种子渠道。
- **扩散路径**: 种子用户（日本在华驾驶学习微信群 ~1000 人）→ 在日华人圈（口碑、社群、KOC）→ 后续可复制到其他地区/语种。
- **MVP 范围**: 仅服务上述种子用户与早期在日华人，功能与场景收窄以保证可交付与可合规。

### 1.3 商业成功角度（MVP 阶段）

- **验证假设**: 用户是否愿意为「代打电话」付费或持续使用（留存、复购/复用的意愿）。
- **核心指标**: 完单率（诉求被满足的比例）、用户 NPS/复购率、单案闭环时长与人工介入率。
- **变现预留**: 文档中预留「计费单元」（按通/按案/订阅）的设计空间，MVP 可先免费或低价验证。

## 2. 目标用户与场景（MVP）

### 2.1 种子用户画像

- **来源**: 你建立的「日本在华驾驶学习」微信群，约 1000 人。
- **特征**: 与日本有强关联（赴日考驾照、在日生活/工作/留学计划），有日语环境下的沟通需求，但可能存在语言、时间或心理门槛。
- **扩散**: 通过他们推荐给更多在日华人（留学生、工作者、家属等）。

### 2.2 MVP 核心场景（优先级）

| 优先级 | 场景         | 用户诉求简述           | 代打对象示例       |
|--------|--------------|------------------------|--------------------|
| P0     | 咨询         | 询问营业时间、规则、所需材料等 | 驾校、区役所、店铺 |
| P0     | 订座/预约    | 餐厅、诊所、美容院等预约     | 商户电话           |
| P1     | 购物/下单    | 电话下单、确认库存、配送     | 本地商户、客服     |
| P1     | 投诉/售后    | 退换货、投诉、进度查询       | 商家/运营商客服   |

MVP 建议先做 P0（咨询 + 订座），再扩展 P1。

## 3. 产品功能需求（MVP）

### 3.1 端到端流程概览

```
用户 → [文字输入诉求+背景] → 系统 → [AI 语音电话至对象] → 对方
                ↑                                              ↓
                └── [结果反馈：文字/语音/电话/短信/邮件] ←───────┘
                     （用户授权方式，可多轮）
```

### 3.2 功能模块

#### 3.2.1 诉求与背景采集（文字）

- **输入方式**: 文字（聊天/表单均可，MVP 可先表单或简单对话）。
- **必采信息**（依场景可配置）:
  - 用户诉求（一句话 + 可选详情）。
  - 目标对象：机构/商户名称、电话（或从预设列表选）。
  - 用户身份/称呼（如「王先生」「李女士」）、可选：会员号、预约日期等。
  - 用户希望的结果呈现方式：文字 / 语音 / 电话回拨 / 短信 / 邮件（多选或单选）。
- **可选**: 用户可用语言（中文/日文等）、时区、可接听回访的时间段。

#### 3.2.2 AI 语音外呼（仿真人电话）

- **能力**: 系统代表用户拨打目标号码，用**语音**与对方沟通（非文字聊天），话术与语气贴近真人。
- **要求**:
  - 使用采集到的诉求与背景生成话术，并在通话中按对方反应调整（多轮对话）。
  - 单案内**记忆**：同一 case 内多通电话或同一通内多轮，需共享上下文（身份、诉求、已有结论）。
- **合规**: 外呼需符合当地电信与营销法规（日本需注意「着信拒否」、特定商法、个人情报保护法等）；MVP 限定为「用户主动发起的代打」，避免主动推销。

#### 3.2.3 结果反馈（用户授权方式）

- **渠道**: 文字 / 语音 / 电话回拨 / 短信 / 邮件。用户在下单时选择一种或多种。
- **内容**: 通话摘要、对方答复要点、下一步建议（如需用户提供材料、到场时间等）。
- **多轮**: 若一次通话未完全解决，可发起后续代打，同一 case 内共享记忆并更新结果反馈。

#### 3.2.4 单案内记忆与状态

- **Case 模型**: 一个「诉求」对应一个 case_id；可包含多通电话、多轮对话。
- **存储**: 每通电话的摘要、关键信息（时间、对方姓名/职务、承诺事项）、未决项。
- **用途**: 下一通电话或下一轮对话时，AI 可引用「上次对方说…」「您之前要求…」，避免重复询问、提升成功率。

### 3.3 非功能需求（MVP）

- **时延**: 从用户提交到「首通外呼」的排队时间可接受在分钟级（非实时秒级）。
- **可用性**: 目标 99% 以上请求被系统接受并进入执行队列；实际接通率依赖运营商与对方接听，需在反馈中说明。
- **安全与隐私**: 用户手机号、通话内容、结果仅用于本单服务与用户授权的反馈，不做营销或转售；存储与传输需加密、访问需鉴权。

## 4. 产品闭环方案（切实可行）

### 4.1 用户侧闭环

1. **入口**: 微信群内链接/小程序/H5（MVP 选一种即可，建议 H5 或简单 Web 表单，便于快速上线）。
2. **提交**: 用户填写诉求、被叫号码、希望的结果反馈方式；提交后获得 case_id 与预计处理时间。
3. **执行**: 系统排队 → AI 外呼 → 记录结果与记忆。
4. **反馈**: 按用户选择推送文字消息/语音/回拨/短信/邮件；若需补充信息或二次代打，引导用户在同一 case 下补充。
5. **结束**: 用户确认「诉求已解决」或「不再需要跟进」，case 关闭；可选满意度与推荐意愿（NPS）。

### 4.2 运营侧闭环

- **监控**: 每案状态（待外呼/进行中/已结束）、接通率、平均通话时长、未接通原因（占线/拒接/空号等）。
- **人工兜底**: 当 AI 无法完成（如对方要求真人、复杂纠纷）时，可转人工或提示用户「建议您亲自致电并已为您整理要点」。
- **种子用户运营**: 在驾驶学习群内收集反馈、优先处理、邀请推荐在日华人；可设简单激励（优先处理、免费额度等）。

### 4.3 商业闭环（MVP 可简化）

- **计费**: 可按「每案」或「每通电话」计费；MVP 可免费或「前 N 案免费」以验证意愿。
- **支付**: 若收费，需接入支付（如 Stripe、支付宝/微信，视用户主体与合规而定）；日本落地需考虑本地支付习惯与发票。

## 5. 外部接入需求、信息与工具许可（需人为处理）

以下为**必须由人或法务/商务处理**的依赖，并需配套**清晰教程与引导**（见第 6 节）。

### 5.1 电信与通话能力

| 类型           | 说明                     | 需人为处理内容                         |
|----------------|--------------------------|----------------------------------------|
| 语音外呼 API   | 向日本号码发起语音通话   | 选择供应商（Twilio / 阿里云 / 日本运营商合作等），签约、申请日本号码或合规外呼资质 |
| 语音合成/识别  | TTS 与 ASR，支持日/中    | 选型（云厂商或专用语音模型）、API 密钥、合规与数据出境（日本/中国） |
| 短信/邮件      | 结果反馈渠道             | 短信：日本 SMS 网关签约；邮件：SMTP 或 transactional email 服务 |

**信息与许可**:

- 日本外呼：需确认是否需「電気通信事業者」登记、着信拒否对应、主叫号码显示规则。
- 通话录音与留存：日本需符合個人情報保護法、录音告知义务（若录音）；用户协议中明确「代打与录音」的同意条款。

### 5.2 AI 与数据

| 类型       | 说明                     | 需人为处理内容                         |
|------------|--------------------------|----------------------------------------|
| 大模型/Agent | 生成话术、多轮对话、摘要 | 选型（OpenAI/Claude/本地等）、API Key、合规（数据是否可出境、是否可用于训练） |
| 存储与记忆 | Case、通话摘要、用户信息 | 数据库与对象存储部署地（日本/其他）、备份与访问策略、隐私政策对齐 |

### 5.3 用户触达与授权

| 类型     | 说明                     | 需人为处理内容                         |
|----------|--------------------------|----------------------------------------|
| 微信     | 群内链接、消息通知（若用） | 公众号/企业微信配置、模板消息或客服消息权限 |
| 邮件/短信 | 结果反馈                 | 用户同意接收、退订机制、内容合规       |
| 回拨     | 结果通过电话告知用户     | 外呼能力同上；需用户授权「可回拨本号码」 |

### 5.4 合规与法务

- **用户协议与隐私政策**: 明确代打范围、数据用途、录音（若有）、第三方共享（电信/AI 供应商）、保留期限、用户权利。
- **日本**: 個人情報保護法、特定商取引法（若涉及电商/预付）、電気通信事業法相关。
- **中国**（若用户在中国）: 个人信息保护法、跨境提供规则（若数据到境外）。

### 5.5 清单小结（人为处理项）

- [ ] 选定并签约**外呼/语音**服务商（日本可用号码或合规外呼）。
- [ ] 选定 **TTS/ASR** 服务并配置密钥与合规。
- [ ] 选定 **LLM/Agent** 服务并配置 API、合规与数据策略。
- [ ] 部署**存储与记忆**（数据库/对象存储），确定地域与访问控制。
- [ ] 配置**短信/邮件**通道（若 MVP 需要）。
- [ ] 撰写并上线**用户协议与隐私政策**（含代打、录音、数据共享）。
- [ ] 确认日本侧**电信与个人信息**相关合规动作（必要时咨询当地律师）。
- [ ] **微信**侧：公众号/企微配置与消息权限（若用微信触达）。

## 6. 教程与引导（人为处理者用）

以下为面向**项目负责人或运营**的「按步骤做完即可打通」的引导，便于将 5.1–5.5 落地。

### 6.1 外呼与语音能力开通（示例：Twilio 日本）

1. **注册**: 登录 [Twilio](https://www.twilio.com)，完成账号与计费设置。
2. **日本号码**: Console → Phone Numbers → Buy a number → 选择日本（JP）、Voice 能力；若无可购，需提交申请或联系销售。
3. **合规**: 阅读 Twilio 日本合规说明（主叫显示、录音告知等），在应用中实现「接通前播放告知」若需录音。
4. **密钥**: 获取 Account SID、Auth Token，存入环境变量或密钥管理，勿提交代码库。
5. **测试**: 用 Twilio 控制台或脚本发起一次测试呼叫，确认可接通并录音/转写（若用）。

**教程产出物**: 一份「Twilio 日本语音开通清单」（含截图与每一步勾选），存于项目 `docs/external-setup/`。

### 6.2 TTS/ASR 与 LLM 开通

1. **TTS/ASR**: 选择一家（如 Azure Speech、Google Cloud、或日本本地服务），在对应控制台开通项目、创建密钥、确认支持日语（及中文若需要）。
2. **LLM**: 选择 API 提供商（如 OpenAI/Anthropic/国内可用的 API），创建 API Key，确认调用地域与数据政策。
3. **环境变量**: 将各服务的 Key/Endpoint 写入 `.env.example` 并文档化；生产使用密钥管理服务。

**教程产出物**: `docs/external-setup/tts-asr-llm-setup.md`，列出各厂商开通步骤与必填环境变量。

### 6.3 用户协议与隐私政策

1. **模板**: 使用法务提供的模板或参考同类型产品（代打电话/AI 客服）的条款。
2. **必含**: 服务内容、代打与录音的同意、个人信息的收集/使用/共享/保留、用户权利（查阅、删除、撤回同意）、联系方式、争议解决。
3. **发布**: 在 Web/小程序首屏或提交前勾选处展示链接，并记录用户同意时间与版本号。

**教程产出物**: `docs/compliance/user-agreement-checklist.md`，列出条款章节与上线前检查项。

### 6.4 微信触达（若采用）

1. **公众号/企微**: 注册并认证，获取 AppID/Secret。
2. **消息**: 若用模板消息，需在微信公众平台申请模板并审核；客服消息需开通相应能力。
3. **链接**: 在群内发布 H5 或小程序路径时，确保域名已备案且符合微信外链规范。

**教程产出物**: `docs/external-setup/wechat-setup.md`，步骤化开通与配置。

### 6.5 引导文档的存放与维护

- 所有「人为处理」的教程与清单统一放在 **`docs/external-setup/`** 与 **`docs/compliance/`**。
- 每个文档末尾注明**最后更新日期**与**负责人**；任一外部服务或合规要求变更时，同步更新对应文档。

## 7. 风险与假设

- **合规**: 日本电信与个人信息法规可能随地区或业务形态有额外要求，建议 MVP 前做一次轻量法务确认。
- **接通率**: 对方拒接、占线、非人工应答会影响完单率；需在反馈中透明说明，并设「重试/换时间」策略。
- **滥用**: 代打可能被用于骚扰或欺诈；需用户协议约束、单日/单用户限额与人工抽检。
- **假设**: 种子用户愿意在群内点击链接并填写表单；在日华人存在明确「代打电话」需求且愿为结果付费或持续使用。
